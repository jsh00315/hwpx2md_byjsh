# hwpx2md

한글 문서(`.hwp`, `.hwpx`)를 마크다운(`.md`)으로 바꾸는 변환기입니다. 제목(`#`), 목록, 표, 그림, 각주, **수식(LaTeX `$…$`)** 을 살리고, 변환할 때마다 자동 점검 21가지(C1~C21)를 돌려 어디가 미심쩍은지 알려 줍니다.

## 특징

- `.hwpx`는 직접 읽고, `.hwp`는 먼저 [rhwp](https://github.com/edwardkim/rhwp)로 `.hwpx`로 바꾼 뒤 같은 방식으로 변환합니다.
- 한글 수식 문법을 LaTeX로 바꿉니다. 규칙은 `rules/수식규칙표.csv`에 있어 코드를 고치지 않고 추가할 수 있습니다.
- 애매한 수식은 임의로 바꾸지 않고 `[수식 원문]`으로 남깁니다(원문 보존).
- 폴더 안의 파일을 한 번에 변환하고, 내용이 같은 파일(SHA-256)은 한 번만 변환합니다.
- 원본은 읽기만 합니다. 결과는 전부 `output/` 아래에 씁니다.

## 빠른 시작

1. 파이썬 3.9 이상을 설치합니다. 변환만 할 때는 추가 패키지가 필요 없습니다.
2. 변환할 `.hwp`/`.hwpx`를 `input/` 폴더에 넣습니다. (다른 폴더를 쓰려면 아래 "설정" 참고)
3. `.hwp`를 쓴다면 rhwp를 받습니다(아래 "외부 프로그램").
4. 실행합니다.

```bash
python -X utf8 -I run_all.py
```

결과는 `output/문서키/` 아래에 문서마다 만들어지고, 전체 요약은 `output/점검요약_일괄.csv`에 한 줄씩 쌓입니다.

## 설정

경로는 `config.py` 한 곳에서만 정합니다. 내 컴퓨터에만 맞는 값은 `config_local.example.py`를 `config_local.py`로 복사해 거기에 적습니다. (`config_local.py`는 git에 올라가지 않습니다.)

| 이름 | 뜻 |
|---|---|
| `INPUT_DIRS` | 변환할 폴더 목록(하위 폴더까지 찾음) |
| `OUT_ROOT` | 결과 폴더 |
| `RHWP` | rhwp 실행 파일 경로. `.hwp`를 쓸 때만 필요 |
| `HWP2MD` | hwp2md 실행 파일 경로. 없으면 대조 점검 3개만 건너뜀 |

한글 경로가 깨지지 않도록 폴더는 명령줄이 아니라 설정 파일에 적습니다.

## 외부 프로그램 (선택)

| 프로그램 | 언제 필요한가 | 받는 방법 |
|---|---|---|
| rhwp | `.hwp` 변환 | <https://github.com/edwardkim/rhwp/releases/latest> 에서 Windows용 `rhwp.exe`를 받아 `bin/rhwp.exe`에 둡니다(또는 `config_local.py`의 `RHWP`에 경로). |
| hwp2md | 점검 C9, C10, C14의 두 번째 변환기 대조. 없어도 변환은 됩니다. | Rust가 있으면 `cargo install hwp2md` (GPL-3.0). |

받은 파일은 먼저 안전한지 직접 확인하세요. 이 저장소는 외부 프로그램을 포함하지 않습니다.

## 폴더 구조

```
hwpx2md_by_jsh/
├─ run_all.py            폴더 전체 일괄 변환 (여기만 실행하면 됨)
├─ config.py             경로 설정
├─ config_local.example.py  내 컴퓨터용 설정 견본
├─ converter/
│  ├─ hwpx_common.py     공통 도구(해시, 파일 앞 바이트 등)
│  ├─ hwpx_reader.py     hwpx(zip+XML)를 읽어 문서 구조로 만듦
│  ├─ hwpeq2latex.py     한글 수식 -> LaTeX
│  ├─ md_writer.py       문서 구조 -> 마크다운
│  ├─ checker.py         자동 점검 C1~C21
│  └─ convert_doc.py     문서 한 개를 위 순서대로 변환
├─ rules/                수식규칙표, 수식명령사전, 요소분류표, 목록기호 (csv)
├─ tools/                eye_check.py(PDF 대조 화면), problem_list.py(문제 부분 목록)
├─ tests/                수식 변환 시험
├─ input/  output/       넣을 곳 / 결과 (내용은 git 제외)
```

## 변환 결과 파일 (문서 한 개당)

| 파일 | 내용 |
|---|---|
| `문서키.md` | 최종 마크다운 |
| `문서키_점검용.md` | 수식마다 번호 표시를 붙인 점검용 |
| `문서키_점검.json`, `_점검.txt` | 점검 21가지의 판정과 값 |
| `문서키_수식대조.csv` | 수식마다 원문, LaTeX, 상태(변환/원문보존) |
| `문서키_미지원목록.csv` | 변환하지 못한 개체 |

## 수식 규칙 추가하기

`[수식 원문]`으로 남은 수식의 명령어는 `output/미지원수식명령_일괄.csv`에 모입니다. 필요한 것을 `rules/수식규칙표.csv`에 한 줄 추가(열: 명령, 종류, LaTeX, 대소문자구분, 비고)한 뒤 다시 변환하면 됩니다.

## 시험

```bash
python -X utf8 -m unittest discover -s tests -v
```

수식 변환 9개 시험이 있습니다.

## 알려진 한계

- 제목 판정이 약합니다. 개요 수준,스타일 이름이 없는 문서는 글자 모양으로 추정해서 놓치는 제목이 있습니다.
- 위첨자·굵게 같은 글자 서식은 반영하지 않습니다.
- 점검 C17의 "번호 건너뜀"은 두 가지입니다. 원본 문서가 번호를 건너뛴 경우(그 번호의 글자가 원본에 없음)와, 번호를 글자로 직접 친 캡션이라 점검이 세지 못한 경우입니다. 2006~2025년 자료 24개 중 7곳에서 확인했고, 우리가 글자를 빠뜨린 곳은 없었습니다.
- 한글의 문단 번호 기능이 그려 주는 번호(`<그림 2-2>` 등)와 글머리표는 `header.xml`의 번호 정의를 읽어 순서대로 세어 넣습니다. 원본 .hwp를 rhwp로 그린 PDF와 캡션 번호를 대조했습니다: 2024·2025년 수도권 설명자료 3개는 11개 모두 번호·순서가 같았고, 2023년판은 우리 쪽에 `<표 3-1>` 1개가 더 있습니다(번호 정의에는 있으나 rhwp PDF에는 안 그려져 어느 쪽이 맞는지 모름). 한컴 프로그램 화면과는 대조하지 않았고, 글머리표는 PDF와 대조하지 않았습니다. 장이 바뀌면 번호가 다시 1로 돌아가는 규칙 같은 것은 구현하지 않았습니다.
- 한컴 뷰어에서의 모습은 확인하지 않았습니다. 확인은 마크다운 미리보기(KaTeX)와 PDF 눈 대조 기준입니다.

- 주의해주세여... 많이 알려주십쇼
